Chapter 10

Architecture & User Feedback

Everything from the previous nine chapters assembles into one architecture. Start with the simplest version — query in, model, answer out — and add each component only when you need it. Then close the loop: user feedback is the fuel for everything you'll improve next.

The full AI application architecture

The mature shape of a production AI app. Nobody starts here — each box was added to solve a real problem.

The user feedback flywheel

Shipping isn't the end of the loop — it's the beginning. Products that harvest feedback improve; products that don't, stall.

Key takeaways

  • Grow the architecture, don't design it upfront Start with query → model → response; add context, guardrails, routers, and caches when real problems demand them.
  • Route for cost Sending easy queries to cheap models and hard ones to strong models is one of the biggest production savings available.
  • Observability is not optional Log, trace, and continuously evaluate production traffic — quality drops silently otherwise.
  • Feedback is the moat Explicit and implicit signals, converted into evals and training data, make the product better every cycle. That loop is what competitors can't copy.
